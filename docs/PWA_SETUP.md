# Clarify PWA Setup

This document explains the Progressive Web App (PWA) implementation for Clarify.

## Overview

Clarify is now a fully functional PWA that can be installed on mobile and desktop devices. The app works offline by caching static assets and using the existing offline sync functionality in `lib/notes-service.ts`.

## Features

### Installation
- Install on home screen (mobile)
- Install as desktop app (Chrome, Edge, Safari)
- Standalone app experience

### Offline Support
- View cached notes when offline
- Create and edit notes offline (syncs when back online)
- Cached static assets (fonts, images, CSS, JS)
- Smart caching strategies for Firebase and Google APIs

### Security
- All user notes remain private (not cached by service worker)
- Only static assets and Firebase API calls are cached
- Service worker disabled in development mode
- CSP headers remain enforced

## Architecture

### Files Created

1. **`public/manifest.json`** - Web App Manifest
   - App metadata (name, description, theme colors)
   - Icon definitions
   - Display mode (standalone)
   - App shortcuts (New Note, All Notes)

2. **`public/icons/icon.svg`** - Master icon file
   - Scalable vector logo
   - Orange (#E8613A) on black background
   - Source for generating PNG icons

3. **`app/offline/page.tsx`** - Offline fallback page
   - Shown when user is offline and page isn't cached
   - Auto-redirects when connection restored
   - Explains offline capabilities

4. **`scripts/generate-pwa-icons.js`** - Icon generator
   - Instructions for generating all required PNG sizes
   - Placeholder file creator for development

5. **`scripts/generate-icons.md`** - Icon generation guide
   - Multiple methods (online tools, ImageMagick, Sharp)
   - All required sizes listed

### Configuration

**`next.config.mjs`** - PWA configuration using next-pwa:

```javascript
{
  dest: "public",                          // Service worker destination
  register: true,                          // Auto-register service worker
  skipWaiting: true,                       // Update immediately
  disable: process.env.NODE_ENV === "development"  // Disabled in dev
}
```

**Caching Strategies:**

| Resource Type | Strategy | Cache Duration | Notes |
|--------------|----------|----------------|-------|
| Google Fonts | CacheFirst | 1 year | Static, rarely changes |
| User Avatars | CacheFirst | 30 days | Profile pictures from Google |
| Images | CacheFirst | 30 days | Static assets |
| CSS/JS | StaleWhileRevalidate | 24 hours | Update in background |
| Firebase Data | NetworkFirst | 5 minutes | User notes, auth |
| Google APIs | NetworkFirst | 5 minutes | Auth, user data |
| Notes Pages | NetworkFirst | 24 hours | App pages |
| API Routes | NetworkFirst | 5 minutes | Backend calls |

**`app/layout.tsx`** - PWA meta tags:
- Manifest link
- Apple mobile web app configuration
- Theme colors (light/dark mode)
- Icons (favicon, app icons)
- Viewport settings

## Icon Sizes

The PWA requires these icon sizes:

- **72x72** - iOS, older Android
- **96x96** - Android
- **128x128** - Chrome Web Store
- **144x144** - IE11, Windows
- **152x152** - iPad
- **192x192** - Android, Chrome (required)
- **384x384** - Android
- **512x512** - Splash screens, Android (required)

### Generating Icons

For production deployment, generate PNG icons from the SVG:

**Option 1: Online (Recommended)**
1. Visit https://www.pwabuilder.com/imageGenerator
2. Upload `public/icons/icon.svg`
3. Download and extract to `public/icons/`

**Option 2: ImageMagick**
```bash
magick public/icons/icon.svg -resize 192x192 public/icons/icon-192x192.png
magick public/icons/icon.svg -resize 512x512 public/icons/icon-512x512.png
# ... (see scripts/generate-icons.md for all sizes)
```

**Option 3: Node.js (Sharp)**
```bash
npm install sharp
npx sharp-cli -i public/icons/icon.svg -o public/icons/icon-192x192.png resize 192 192
# ... (see scripts/generate-icons.md for all sizes)
```

## Offline Functionality

### How It Works

1. **Service Worker**: Automatically generated by next-pwa
   - Caches static assets on first load
   - Intercepts network requests
   - Serves cached content when offline

2. **Existing Offline Support**: Already implemented in `lib/notes-service.ts`
   - Draft autosave to localStorage
   - Pending sync queue for offline edits
   - Automatic sync when connection restored

3. **Offline Page**: Custom fallback at `/offline`
   - Shows when user navigates offline to uncached page
   - Auto-redirects when online
   - Explains app capabilities

### User Experience

**Online:**
- Normal app functionality
- Fresh data from Firebase
- Real-time sync

**Offline:**
- View cached notes
- Create/edit notes (stored in localStorage)
- Notes auto-sync when connection restored
- Static assets served from cache
- Offline page shown for uncached routes

## Security Considerations

### What's Cached
✅ Static assets (CSS, JS, fonts, images)
✅ App shell (HTML pages)
✅ Google Fonts
✅ User avatars (profile pictures)
✅ Firebase API calls (short cache, 5 min)

### What's NOT Cached
❌ User notes content (privacy)
❌ Authentication tokens
❌ Sensitive user data
❌ Firebase credentials

### Security Measures

1. **CSP Headers**: Already configured in `next.config.mjs`
   - Restrict script sources
   - Control frame ancestors
   - Limit API connections

2. **Service Worker Scope**: Limited to `/`
   - Can't access parent directories
   - Sandboxed from server

3. **Cache Expiration**: All caches have max age
   - Prevents stale data
   - Regular cleanup

4. **HTTPS Only**: PWAs require HTTPS
   - Enforced by browsers
   - Secure data transmission

5. **No XSS**: Content sanitized in `lib/notes-service.ts`
   - DOMPurify for HTML content
   - Tag stripping for titles


## Troubleshooting

### Icons Not Showing

**Problem**: Install prompt appears but icons are missing

**Solution**:
1. Generate PNG icons (see Icon Generation)
2. Clear browser cache
3. Rebuild app: `npm run build`
4. Unregister service worker in DevTools
5. Refresh page

### Service Worker Not Updating

**Problem**: Changes not reflected after deployment

**Solution**:
1. Update version in `package.json`
2. Rebuild: `npm run build`
3. Clear cache: DevTools → Application → Clear storage
4. Hard refresh: Ctrl+Shift+R (Cmd+Shift+R on Mac)

### Offline Page Not Working

**Problem**: White screen when offline

**Solution**:
1. Check service worker is registered
2. Verify `app/offline/page.tsx` exists
3. Rebuild app
4. Test in incognito mode

### App Not Installable

**Problem**: No install prompt appears

**Solution**:
1. Ensure HTTPS is enabled
2. Check manifest.json is valid (DevTools → Application)
3. Verify 192x192 and 512x512 icons exist
4. Check console for errors
5. Test in Chrome/Edge (best PWA support)

### Firebase Not Working Offline

**Problem**: Firebase errors when offline

**Solution**: This is expected! Firebase requires connection for:
- Authentication
- Real-time updates
- New data fetching

Offline support uses:
- localStorage for drafts
- Pending queue for edits
- Auto-sync when online
